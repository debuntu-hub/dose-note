## 1. 画面仕様

### 1.1 画面遷移図（概念）
```
アプリ起動
  ↓
[生体認証ON?] --YES--> [ロック画面 (LockView)] --> 認証成功 --> [メイン画面]
      |                                                  
      NO                                                 
      ↓                                                  
[メイン画面 (生成・保存)] <---> [一覧画面 (検索・参照)] <---> [設定画面]
  │                              │
  └-> [保存完了] -> 自動遷移 ------┘
```

> **v1.0変更**: 生体認証はデフォルトOFF。設定画面でONにした場合のみLockViewを表示。

### 1.2 画面詳細

#### SC-01: 生成画面（ホーム）
* **初期状態**: アプリ起動時に表示。16文字のランダムパスワードが生成済み。
* **操作**:
    * [再生成]: 新しいパスワードを生成。
    * [コピー]: 表示中のパスワードをクリップボードへ。
    * [保存]: 保存処理を実行。
    * [パスワード編集]: 生成されたパスワードをタップして直接手動編集可能。
    * [ラベル編集]: 複数パスワード時、各ラベルをタップして名称変更可能。
* **パスワード編集仕様**:
    * パスワード欄はTextField（モノスペースフォント）。
    * 自動修正OFF（autocorrectionDisabled）。
    * 大文字自動変換OFF（textInputAutocapitalization: .never）。
    * 手動編集と再生成ボタンは共存（編集後も↻で再生成可能）。
    * 複数パスワード時、ラベルもTextField化し編集可能。
* **入力項目**:
    * サービス名（必須）: 候補表示あり。
    * ユーザーID: 直前値/メルアド形式のクリップボード内容を自動セット。
    * メモ: 任意。

#### SC-02: 一覧画面
* **表示**: 登録済みアイテムのリスト。
* **検索**: サービス名、IDでインクリメンタルサーチ。
* **アクション**:
    * タップ: パスワード（またはID）をコピー。
    * 長押し: 詳細メニュー / 編集 / 削除。

#### SC-03: 設定画面
* 生体認証ロック ON/OFF トグル（デフォルト: OFF）
  * ON→OFF: 即座にロック解除、KeychainキーのACLから`.biometryAny`を除去
  * OFF→ON: KeychainキーのACLに`.biometryAny`を付与
* クリップボードクリア時間設定（10秒〜120秒）
* 自動ロック時間設定（即時〜5分）
* TapKey Premium 購入 / 復元
* バージョン情報

### 1.3 非機能要件（v1.0追加）
* **対象端末**: iPhone専用（iPad非対応）
* **最低OS**: iOS 17+
* **暗号化申告**: ITSAppUsesNonExemptEncryption = NO（Apple標準CryptoKitのみ使用）

## 2. データモデル & セキュリティ

### 2.1 VaultItem（SwiftData）
| フィールド | 型 | 説明 |
|---|---|---|
| id | UUID | 一意識別子 |
| title | String | サービス名（平文検索用? 要検討だがv0.1はメタデータ暗号化せずUX優先か、全暗号化か要決定） |
| encryptedData | Data | 暗号化されたJSON（username, password, notesを含む） |
| createdAt | Date | 作成日 |
| updatedAt | Date | 更新日 |

> **セキュリティ方針**: 
> 検索性を考慮し、`title` はCore Data上で平文保持、または検索用インデックスのみ平文保持し、実体は暗号化するなどの構成とする。
> ※仕様書v0.1では「独自クラウドしない」「ローカル完結」なので、Core Data自体がサンドボックス内にある。
> **決定**: `secretData` `notesData` のみを暗号化し、検索用 `title` `username` は平文（または難読化）でCore Data保持とする（検索速度と実装のバランス）。

### 2.2 暗号化仕様
* **アルゴリズム**: AES-GCM (CryptoKit)
* **鍵管理**: SymmetricKeyを生成し、Keychainに保存。
* **アクセス制御**: 
  * 生体認証ON時: `kSecAttrAccessControl` に `.biometryAny` を指定
  * 生体認証OFF時: `kSecAttrAccessibleWhenPasscodeSetThisDeviceOnly` のみ（生体認証不要）
  * トグル変更時: 既存キーを読み出し、新しいACLで再保存（`EncryptionManager.reSaveKey()`）

## 3. エラーハンドリング

### 3.1 認証エラー
* Face ID/Touch ID 失敗時 -> 再試行ボタン表示。データにはアクセスさせない。

### 3.2 保存エラー
* 必須項目不足 -> エラーダイアログではなく、対象フィールドへフォーカス＋揺れアニメーション等でガイダンス。
* 暗号化/保存失敗 -> アラート表示「保存できませんでした」。

### 3.3 クリップボード制御
* アプリがバックグラウンドに回った時点でクリップボードをクリア（または指定時間後）。

---

## 4. UI/UX 要件

* **起動 = 生成**: 起動したら即座に「使えるパスワード」がある状態を作る。
* **ワンタップ**: コピー、保存のアクション数を最小にする。
* **フィードバック**: コピー時や保存完了時にHapsticフィードバックを返す。
