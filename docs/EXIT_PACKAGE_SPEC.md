# 📦 アプリ説明パッケージ自動生成仕様書

本仕様書は、アプリ売却時に買い手へ提供する「アプリ説明パッケージ」の自動生成ルールを定義する。
開発ストーリーや感情を排除し、**数字・構造・再現性** のみを伝える。

---

## 1. 生成物の構成

コマンド実行（Copilotへの指示）により、`exit_package/` フォルダ配下に以下を生成する。

```
exit_package/
 ├─ 01_overview.md        （概要）
 ├─ 02_financials.md      （FCF・数字）
 ├─ 03_product.md         （プロダクト仕様）
 ├─ 04_tech.md            （技術）
 ├─ 05_operations.md      （運用）
 └─ 06_exit_summary.md    （売却条件まとめ）
```

---

## 2. 自動生成プロンプト（AI指示用）

以下のプロンプトをCopilotに入力することで、パッケージ一式を生成する。

```markdown
docs/ 配下の以下を参照し、
売却用アプリ説明パッケージを生成してください。

参照元：
- PRD.md
- SRS.md
- FCF_REPORT.md
- FEATURE_FCF_REPORT.md
- CEO_DASHBOARD.md

要件：
- 買い手視点で簡潔に
- 感情・開発ストーリーは含めない
- 数字はFCF中心
- exit_package/ 配下に6ファイルを生成

出力仕様：

01_overview.md（概要）
# アプリ概要
- アプリ名：
- カテゴリ：
- 対象ユーザー：
- 提供価値（1文）：
- 現在の状態：運用中 / 自動化済み
- 売却理由：安定収益・次の投資先あり

02_financials.md（財務）
# 財務サマリー
- 月次FCF：+____ 円
- 6ヶ月平均FCF：+____ 円
- FCFの安定性：±____ %
## 内訳
- 売上：
- Apple手数料：
- その他コスト：
※ 元データは CSV で提供可能

03_product.md（プロダクト）
# プロダクト仕様
- 主機能一覧
- Free / Premium 区分
- 課金導線概要
- 将来の拡張余地

04_tech.md（技術）
# 技術構成
- 言語 / フレームワーク：
- 永続化方式：
- 課金方式：
- 外部依存：
- ビルド方法：

05_operations.md（運用）
# 運用状況
- 日次作業：なし / 最小
- 月次作業：FCF集計のみ
- 障害対応：手順書あり
- 属人性：なし

06_exit_summary.md（売却条件）
# 売却条件まとめ
- 希望売却価格：
- 算定根拠（月次FCF × 倍率）：
- 引き継ぎ内容：
- 引き継ぎ期間：
```

---

## 3. 各ファイルの記載方針

### 01_overview.md
「何をするアプリか」と「なぜ売るのか」だけを書く。
売却理由はポジティブに（例：次の投資先が見つかったため）。

### 02_financials.md
FCF（キャッシュフロー）が全て。
PL（損益計算書）よりも「実際にいくら手元に残るか」を最優先で記載。

### 03_product.md
機能の詳細より「課金ポイント」と「拡張性」を重視。
買い手が「こうすればもっと儲かる」と想像できる余地を残す。

### 04_tech.md
「メンテナンスが楽であること」をアピール。
特殊な技術を使っていないこと、標準的であることを強調。

### 05_operations.md
「あなたが買っても運用できます」という安心感を与える。
作業時間の短さと自動化レベルを強調。

### 06_exit_summary.md
条件提示。CEOが決めた価格と条件を記載。
曖昧さを残さない。

---

**最終原則**：買い手は「事業」を買うのであり、「コード」を買うのではない。
