# TapKey 仕様書（v0.1）

**アプリ名：TapKey**

サブタイトル（仮）：*One‑tap password creation & save*

## 0. 前提・方針

※ 本アプリの名称は **TapKey** とする

* 個人開発を前提とし、**安全性と実装現実性の両立**を最優先する
* ローカル完結型アプリとし、独自クラウドは使用しない
* iOS標準のセキュリティ機構（Keychain / Secure Enclave / LocalAuthentication / CryptoKit）を最大限活用する
* 「自分が毎日使えること」を最上位要件とする

---

## 1. PRD（プロダクト要件）

### 1.1 目的

* 各種サービスの認証情報を安全に保管し、**入力の手間を極力なくすこと**を主目的とする
* 特に「新しく作成したパスワードをアプリに保存する際の手入力」を最小化する
* パスワード管理アプリを「開く・考える・入力する」という行為自体を減らす

### 1.2 想定ユーザー

* 個人（自分自身）

### 1.3 MVP（最小実装範囲）

**最重要UX要件："極力入力しない"**

* 新規パスワード登録時の入力を極限まで減らす

  * パスワードは生成結果をそのまま保存
  * 手入力を前提としない
* パスワード情報の追加 / 編集 / 削除

  * サービス名（URL・ドメインから自動補完）
  * ユーザーID（直前入力やクリップボードから自動取得）
  * パスワード（生成結果を自動セット）
  * メモ
* 一覧表示および検索（1〜2文字で即ヒット）
* 生体認証ロック（Face ID / Touch ID）
* ワンタップ操作

  * IDコピー
  * パスワードコピー
* クリップボードコピー

  * 一定時間後の自動クリア
* 完全オフライン動作（ローカル保存）

※ 初期MVPでは「新規作成 → 保存」までを最短動線で完結させる

### 1.4 v1.0 以降の拡張候補

* iOS Password AutoFill 連携
* TOTP（2段階認証コード）保存
* パスワード強度評価
* パスワード使い回し検出
* CSV / JSON によるインポート・エクスポート（強警告付き）

### 1.5 非対応（初期段階では実施しない）

* 独自クラウド同期
* Web版 / Windows版
* チーム・複数人共有機能

## 2. セキュリティ設計

### 2.1 基本方針

* 機密データは必ず暗号化して保存する
* 暗号鍵はアプリ内に保持せず、Keychain に格納する
* 鍵取得時に生体認証を必須とする

### 2.2 ロック・鍵管理方式

**方式A（採用案）**

* データ本体：アプリ内データベース
* 暗号鍵：Keychain に保存
* アプリロック解除：Face ID / Touch ID
* マスターPWは設けない

理由：

* UX が良好
* 実装が比較的安全
* 事故ポイントが少ない

### 2.3 暗号方式

* 暗号ライブラリ：CryptoKit
* データ暗号化：AES-GCM
* 鍵長：256bit
* 鍵生成：初回起動時にランダム生成

### 2.4 クリップボード管理

* コピー後、指定秒数で自動クリア
* アプリがバックグラウンド遷移した場合は即時クリア

### 2.5 想定脅威と対策

| 脅威        | 対策                 |
| --------- | ------------------ |
| 端末紛失      | 生体認証 + Keychain 保護 |
| 画面覗き見     | パスワードはデフォルト伏せ字     |
| スクリーンショット | 重要画面では制限・検知        |
| バックアップ流出  | エクスポート時に暗号化 + 警告   |

## 3. 画面設計（概要）

### 3.1 v0.1 メイン画面遷移（最重要）

**基本思想：起動から保存まで、迷わせない1本道**

```
アプリ起動
  ↓
生体認証（初回 / 復帰時）
  ↓
メイン画面（= 生成画面）
  ↓
[生成] をタップ
  ↓
パスワード自動生成
（この時点で仮保存状態）
  ↓
サービス名 / ID を最小入力
（自動補完・前回入力優先）
  ↓
[保存] をタップ
  ↓
保存完了 → 一覧に即反映
```

※ v0.1 では「一覧 → 追加」ではなく、**起動＝生成**を基本動線とする

---

### 3.1.1 生成画面 UI 仕様（v0.1 固定）

**目的：ユーザーに考えさせず、安全なパスワードを即座に作らせる**

#### 初期表示状態

* パスワード文字数：**16文字（固定）**
* 使用文字種：

  * 英大文字：ON
  * 英小文字：ON
  * 数字：ON
  * 記号：ON
* パスワード欄：自動生成済み（伏せ字表示）
* カーソルフォーカス：なし（即コピー可能）

#### 操作要素

* [再生成] ボタン

  * タップ毎に新しいパスワードを生成
  * 再生成時も自動的に仮保存状態を更新
* [コピー] ボタン

  * 現在表示中のパスワードを即コピー
* [保存] ボタン

  * サービス名 / ID が未入力の場合は入力を促す

#### 入力補助仕様

* サービス名

  * 直前に保存したサービス名を候補表示
  * URL / ドメイン入力時は自動整形
* ユーザーID

  * 直前入力値を自動セット
  * クリップボード内容がメール形式の場合は候補表示

#### UX 制約（v0.1）

* 文字数・記号ON/OFFのカスタマイズは不可
* 強度メーター表示は行わない

※ v0.1 では「安全な初期値を信じて使わせる」ことを優先する

---

### 3.1.2 初回起動時ガイダンス（v0.1）

**目的：説明を読ませず、このアプリの使い方を10秒で理解させる**

#### 表示タイミング

* アプリ初回起動時のみ表示
* 生体認証完了後に表示

#### 画面構成（1画面完結）

**タイトル**

* 「考えずに作って、すぐ保存」

**説明文（最大3行）**

* このアプリは、パスワードを *考える・入力する*手間を減らします。
* 起動すると、すでに安全なパスワードが生成されています。
* コピーして使い、名前を付けて保存するだけです。

**UI要素**

* [すぐ始める] ボタン

  * タップで生成画面へ遷移

#### 制約

* チュートリアルの複数ページ化は行わない
* 設定説明・セキュリティ詳細説明は行わない

※ v0.1 では「理解させる」より「触らせる」を優先する

## 3.6 エラーハンドリング仕様（v0.1）

**目的：ユーザーを止めず、データを壊さず、不安にさせない**

### 3.6.1 基本方針

* 原則として「操作不能になるエラー表示」は行わない
* ユーザーの入力ミスはエラーではなく**ガイダンス**として扱う
* 内部エラー（暗号・保存失敗など）はデータ保護を最優先する
* v0.1 では詳細な技術エラー表示は行わない

---

### 3.6.2 想定エラーと挙動

#### A. 生体認証に失敗した場合

**発生条件**

* Face ID / Touch ID 認証失敗
* 生体認証キャンセル

**挙動**

* 再試行を促す
* 一定回数失敗した場合は OS 標準の挙動に委ねる
* パスワードデータには一切アクセスさせない

**UI**

* システム標準ダイアログのみ使用

---

#### B. サービス名・ID 未入力で保存しようとした場合

**発生条件**

* [保存] タップ時に必須項目が空

**挙動**

* 保存処理は行わない
* 該当入力欄にフォーカスを移動

**UI**

* エラーダイアログは表示しない
* プレースホルダまたは補足テキストで入力を促す

---

#### C. 暗号化・保存処理に失敗した場合

**発生条件**

* CryptoKit エラー
* Core Data 保存失敗

**挙動**

* データは保存しない
* 仮保存状態は破棄する

**UI**

* シンプルなアラート表示

  * 例：「保存できませんでした。もう一度お試しください。」

※ 技術的詳細は表示しない

---

#### D. 保存前に画面遷移・アプリ終了が発生した場合

**発生条件**

* 保存前にアプリがバックグラウンドへ遷移
* アプリ終了

**挙動**

* 仮保存データは自動破棄
* 次回起動時に新しいパスワードを生成

**UI**

* 確認ダイアログは表示しない

---

#### E. クリップボードコピー失敗

**発生条件**

* OS 制限等によりコピー不可

**挙動**

* 再コピー可能な状態を維持

**UI**

* 明示的なエラー表示は行わない

---

### 3.6.3 v0.1 で行わないエラー処理

* ログイン不能状態への誘導
* 強制クラッシュ防止のための複雑な復旧フロー
* ユーザー向け詳細エラーコード表示

※ v1.0 以降でログ出力・診断機能を検討

## 4. 実装アーキテクチャ

### 4.1 技術スタック

* UI：SwiftUI
* 永続化：SwiftData
* 暗号化：CryptoKit
* 鍵管理：Keychain
* 生体認証：LocalAuthentication

### 4.2 データモデル（最小構成）

**VaultItem**

* id: UUID
* title: String
* encryptedData: Data（暗号化済み）
* createdAt: Date
* updatedAt: Date

**SecretPayload**（暗号化されて保存）

* username: String
* password: String
* note: String

## 8. 収益化設計

### 8.1 基本方針

* セキュリティ・信頼性を最優先し、広告モデルは採用しない
* 継続的な運用コストが発生しないため、サブスクリプションモデルは採用しない
* ユーザーが「便利だと感じた時点」で自然に支払える形を目指す

### 8.2 課金モデル

**フリーミアム + 買い切り課金（1回課金）** を採用する

* 無料：基本機能を体験可能
* 有料（買い切り）：利便性・効率を大きく向上させる機能を解放

### 8.3 無料プランで提供する機能

* 保存件数の上限（例：10件まで）
* パスワード生成機能
* ID / パスワードのコピー
* 検索機能
* 生体認証ロック

※「生成 → 保存 → 利用」という基本体験は無料で完結させる

### 8.4 有料（買い切り）で解放する機能

* 保存件数の無制限化
* iOS Password AutoFill 連携
* TOTP（2段階認証コード）管理
* データエクスポート / インポート
* スクリーンショット / 共有シート連携による保存補助機能（将来拡張）

### 8.5 価格帯の想定

* 想定価格帯：¥600 〜 ¥1,200
* 初期リリース時の目安価格：¥980

理由：

* 衝動買い可能な価格帯
* セキュリティアプリとしての信頼感を損なわない
* 長期利用を前提とした心理的ハードルが低い

### 8.6 課金タイミング設計

* 保存件数上限到達時に案内を表示
* 有料機能（AutoFill / エクスポート等）利用時に説明付きで案内
* 強制的なロックや機能停止は行わない

### 8.7 App Store 表示上の注意点

* 課金は買い切りであることを明確に記載
* データはローカル保存であることを明示
* 広告・トラッキングを行わないことを強調
